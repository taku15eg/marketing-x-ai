# DECISIONS.md — 意思決定ログ

> **このファイルの役割**: 「なぜAではなくBにしたのか」を時系列で記録する。
> 1ヶ月後に改修するとき、判断の理由を振り返れないと一貫性が崩壊する。
> 作業後、重要な判断をしたら「この意思決定をDECISIONS.mdに追記して」と指示すること。

---

## 記録フォーマット

```
### YYYY-MM-DD: [判断の要約]
**選択肢**: A vs B (vs C)
**決定**: B
**理由**: [なぜBなのか。1-3行]
**影響範囲**: [この決定が影響するファイル/機能]
```

## 戦略レベルの決定（Phase 0検証から確定済み）

### 2026-03-07: DOMのみ → Vision API必須
**選択肢**: DOM解析のみ vs Vision API + DOM
**決定**: Vision API + DOM
**理由**: 日本のLPは画像ベースが主流。DOMだけでは訴求の核心（画像内テキスト・レイアウト構造）を取れない。SEVENDEX LP検証で確認。
**影響範囲**: 分析エンジン全体、API費用設計、プロンプト設計

### 2026-03-08: コピー生成 → 構造変化図示
**選択肢**: AIがコピー文言を生成 vs 構造変化のみ図示
**決定**: 構造変化のみ図示
**理由**: AIコピーの品質問題（ブランドトーン不一致、薬機法リスク）。構造変化の方が信頼され、デザイナー/エンジニアが使いやすい。
**影響範囲**: 依頼書パック設計、プロンプト設計、UIデザイン

### 2026-03-08: Chrome拡張本体 → Webダッシュボード本体
**選択肢**: Chrome拡張がメイン vs Webダッシュボードがメイン
**決定**: Webダッシュボードがメイン
**理由**: 成果物（分析結果URL、依頼書）が「外に出る」にはWeb URLが必要。Chrome拡張内の結果は共有不能。AhrefsもDeepLもWeb本体+ブラウザ拡張の構造。
**影響範囲**: プロダクト全体アーキテクチャ、技術スタック、マーケティング戦略

### 2026-03-08: SoR主語 → SoR副産物
**選択肢**: データ蓄積がMOAT vs 分析の深さがMOAT
**決定**: 分析の深さがMOAT。SoRは副産物
**理由**: ユーザーインタビューで価値の源泉は「深さ」。蓄積は時間経過で自然に起きるが、それ自体は課金動機にならない。
**影響範囲**: 課金設計、ポジショニング、マーケメッセージ

### 2026-03-08: LP分析のみ → 6タブ拡張（段階的）
**選択肢**: LP分析に特化 vs マーケティング全体をカバー
**決定**: 6タブで段階的に拡張。Phase展開と連動
**理由**: 「聞き方を知らない人」にはLP分析だけでは不十分。URL1つから全体像が見えるのが本質的価値。ただし一度に全部は作らない。
**影響範囲**: ロードマップ、課金設計、技術設計

### 2026-03-12: 梶谷式11ポイント準拠のプロジェクト構造に移行
**選択肢**: 現状の70+ファイル並列構造 vs PLAN.md中心の進捗駆動構造
**決定**: PLAN.md + DECISIONS.md + CLAUDE.md更新で梶谷式に準拠
**理由**: Claude Codeでの実装フェーズに入る際、「記憶喪失の天才」が毎回読む引き継ぎメモが必要。設計書群は参照資料として残しつつ、実行はPLAN.md駆動に。
**影響範囲**: Claude Code用CLAUDE.md、開発ワークフロー全体
