# CLAUDE.md — Publish Gate 最終版

## このプロダクトの本質

「何を聞くべきかすら知らない人」のために、「聞かなくても答えが出る」プロダクト。

URLを入れるだけで、LP改善だけでなくマーケティング全体（市場傾向・流入構造・広告訴求・競合・事業分析）が見える。バイブコーディングの先、バイブマーケティングの先にいる。

## ターゲット

できたばかりのマーケティング部門で、マーケティングを任された人。まだその領域を熟知していない。兼務で忙しい。深い分析もディレクションもできない。縦割り組織でデザイナー・エンジニアと十分に協業できない。依頼書や仕様書を書く時間もない。

この人にとって、Publish Gateは「URLを入れるだけで、プロのマーケ責任者がやることを全部やってくれるもの」。

## プロダクト構造：Webダッシュボード＋Chrome拡張の二面体

### Webダッシュボード（本体）
- AhrefsのSite Explorerと同じ体験。URL入力→結果一覧→深掘り
- 分析結果は公開URLとして共有可能（バイラルの起点）
- SEOの受け皿（ツールページ・ブログ・結果ページの全てが検索対象）

### Chrome拡張（リテンション＋リマーケティング）
- ブラウザに常駐し「LP改善したいと思った瞬間にそこにいる」存在
- 拡張アイコンの物理的可視性が口コミを誘発

## ダッシュボード 6タブ構造

### タブ1：LP分析（Free〜。Phase 0確認済み）
データソース：URL入力のみ（Vision API + DOM）
Free=課題一覧（概要）、Starter=詳細+依頼書+薬機法チェック+計測設計

### タブ2：広告訴求（Starter〜）
データソース：LP分析結果から逆算
Google Ads RSA見出し15パターン、Meta Ads、PMax、ディスプレイ
LP訴求との整合性チェック、推奨ターゲット/セグメント

### タブ3：市場分析（Pro〜）
データソース：GSC連携 + キーワードプランナー
流入クエリ一覧、検索ボリューム推移3-5年、市場傾向の示唆
重要クエリ特定、拡張すべき市場

### タブ4：流入分析（Pro〜）
データソース：GA4連携
参照元URLランキング、セッション占有率、媒体別、時系列推移

### タブ5：競合分析（Pro〜）
データソース：AI推定 + 公開情報
競合LP構造比較、訴求差別化、競合広告訴求推定

### タブ6：事業分析（Business〜）
データソース：AI推定 + 業界データ
市場規模推定、顧客単価感、事業モデル推定、成長余地

## 分析エンジン（4ステップ。Phase 0確認済み）

① 企業を知る — ドメインの企業情報を自動fetch
② ページを見る — Vision API + DOM + CTA分類
③ 診断する — 課題をインパクト順に構造化。薬機法チェック
④ 依頼パックを出す — デザイナー/エンジニア向け。コピー文言は出さず構造変化を図示

## バイラル設計（5ループ）

1. 分析結果URLの共有 → 受け取った側がFree登録
2. 依頼書の「Powered by Publish Gate」 → デザイナー/エンジニアが新規に
3. Chrome拡張アイコンの可視性 → 「何それ？」→口コミ
4. 上長報告レポートの組織内展開
5. SEOコンテンツ→Free分析→上記全ループ起動

全出力物にPublish Gateへの導線。

## 開発ワークフロー（梶谷式11ポイント準拠）

### セッション開始時に必ず読むファイル（この順番で）
1. **CLAUDE.md**（このファイル）— プロダクト定義と開発ルール
2. **PLAN.md** — 現在フェーズの設計図と進捗。「今どこまで終わったか、次は何か」
3. **DECISIONS.md** — 過去の意思決定とその理由

### ドキュメント・ファースト（ポイント2,3）
- コードを書く前に、まずPlan Modeで計画を立てる
- PLAN.mdの該当タスクを確認し、仕様を把握してから実装に入る
- 「とりあえず作って」は禁止。計画→承認→実装の順

### タスク分割（ポイント4）
- PLAN.mdの各Blockが実装単位。1タスク = 独立して動作確認できる粒度
- 巨大な変更を一度にやらない。LEGOブロックのように積み上げる
- 不確実性が高いタスクは、先にリサーチしてRESEARCH.mdにまとめてから実装

### Gitコミット（ポイント7）
- PLAN.mdの1タスク完了ごとに `git commit`
- コミットメッセージは自動生成してよい（日本語可）
- 大きな機能完了時は `git tag` でセーブポイント作成
- ブランチ戦略: `main` ← `feature/block-N-名前` でPR

### 車輪の再発明禁止（ポイント8）
- 認証 → Supabase Auth
- UI → shadcn/ui + Tailwind CSS
- アイコン → Lucide React
- フォーム → react-hook-form + zod
- ゼロからボタン/モーダル/フォーム等を自作しない

### セキュリティ（ポイント9）
- APIキー、シークレットは必ず `.env.local` に隔離
- コードにハードコードされていないか、実装後にセルフチェック
- .gitignore に .env* を含める

### リファクタリング（ポイント10）
- Block 3つ完了ごとに「コードをリファクタリングして」を実行
- 重複コードの解消、未使用コードの削除、ファイル構成の整理

### 意思決定ログ（ポイント11）
- 技術選定、仕様変更、設計判断を行ったら DECISIONS.md に追記
- 「なぜAではなくBにしたか」の理由を1-3行で記録

### 作業完了時
- PLAN.mdの進捗チェックボックスを更新
- 重要な判断があればDECISIONS.mdに追記
- `git commit` でセーブ

### エラー対応（ポイント6）
- エラーメッセージは全文をそのまま読み込む
- 「動かない」だけでは対応しない。ターミナル出力の全文を確認
