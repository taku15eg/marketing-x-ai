# Publish Gate 代替可能性・競合スイッチリスク分析

> 2026-03-20 作成。コードベース実査に基づく。忖度なし。

---

## 結論（先に）

**模倣は「技術的には」容易。だが「プロダクトとして」模倣されるまでには時間差がある。**
**ChatGPT/Claude Codeへのスイッチリスクは「高い」が、全面代替ではなく部分代替。**

致命的なのは「技術的モートがほぼゼロ」という事実。勝負は速度と体験設計で決まる。

---

## 1. 誰でも模倣可能か？ → Yes、ただし条件付き

### 技術スタック上のモート：なし

| 構成要素 | 模倣難度 | 理由 |
|---------|---------|------|
| Claude API呼び出し | 極めて容易 | APIキー取得→プロンプト投入で完了 |
| DOM抽出 + Vision API | 容易 | Puppeteer/Playwright + Claude Vision。公知技術 |
| 企業リサーチ（Step 1） | 容易 | HTML fetch + 正規表現抽出。特殊データソースなし |
| SSRF防御・セキュリティ | 中程度 | 実装しない人が多いが、やること自体は標準的 |
| プロンプト設計 | 中程度 | `prompt-builder.ts`のシステムプロンプトはドメイン知識が詰まっているが、出力JSONを見ればリバースエンジニアリング可能 |
| 薬機法・景表法チェック | やや難 | ドメイン知識が必要。ただしClaude自体がこの知識を持っている |
| 4ステップパイプライン | 容易 | fetch→DOM解析→Claude呼び出し→JSON整形。典型的なLLMアプリパターン |

**実装工数の見積もり**: 中級エンジニア1名で1-2週間あれば核心機能を再現可能。

### 模倣に時間がかかる部分

1. **プロンプトの精度** — 実際のLP数百本を回してチューニングした結果は簡単にコピーできない。ただし、数週間の試行錯誤で追いつける
2. **出力フォーマットの安定性** — JSONパース失敗のエッジケース処理。地味だが品質差になる
3. **依頼パック（ブリーフ）の実用性** — 「デザイナーに実際に渡せる品質」は知見の蓄積が必要

### 模倣不要な部分（そもそもOSSで代替可能）

- Lighthouseがページパフォーマンス分析を無料提供
- PageSpeed InsightsがCWV診断を無料提供
- 各種SEO監査ツール（Screaming Frog等）が構造分析を提供

## 2. ChatGPT/Claude Codeでスイッチされるか？ → 部分的にYes

### 今すぐ代替可能なこと

ターゲットユーザーが **ChatGPTに以下のプロンプトを貼れば、Publish Gateの核心価値の60-70%を再現できる**：

```
このLPのURLを分析して、以下を出力してください：
1. 企業の概要
2. ファーストビューの課題
3. CTA配置の問題点
4. 改善提案をデザイナー向けブリーフとして
5. 薬機法リスクがあれば指摘
URL: https://example.com
```

ChatGPT (GPT-4o) はブラウジング機能でURLを読み取れる。Claude ProjectsやClaude Codeも同様。

### ユーザーがスイッチする具体的シナリオ

| シナリオ | 確率 | 条件 |
|---------|------|------|
| 藤野型（代理店）がChatGPTプロンプトテンプレを作る | **高** | 月4案件なら毎回プロンプト貼っても苦にならない |
| 浦田型（事業会社マーケ）がClaude Projectsを使う | **中〜高** | 「自社LPだけ」なら固定プロンプトで足りる |
| 七條型（マーケ責任者）がチーム全員にChatGPT使わせる | **低〜中** | チーム標準化のためにSaaSの方が管理しやすい |

### Publish Gateが「まだ」優位な点

| 要素 | ChatGPT/Claude Code | Publish Gate |
|------|---------------------|-------------|
| URL入力だけで完了 | △ プロンプト設計が必要 | ◎ ゼロ思考 |
| Vision API（スクショ分析） | ○ GPT-4oはブラウジングで可能 | ○ 同等 |
| 出力の一貫性 | △ 毎回フォーマットがブレる | ○ JSON構造固定 |
| 共有URL | × 不可（チャット画面の共有のみ） | ◎ 専用URL |
| 依頼パック品質 | △ 汎用的 | ○ デザイナー/エンジニア向け特化 |
| 薬機法チェック | ○ Claude/GPT-4oは知識あり | ○ 同等（プロンプト特化の分やや上） |
| 履歴・比較 | × セッション消える | △ MVP未実装だが設計あり |
| 繰り返し実行のコスト | △ 毎回プロンプト準備 | ◎ URL入力のみ |

**核心問題**: 「URL入力だけ」の体験優位性は、ChatGPTのCustom GPTsやClaude Projectsの固定プロンプトで大幅に縮まる。

## 3. 本当のリスク：「中間層の消滅」

Publish Gateの最大リスクは直接競合ではなく、**LLMプラットフォーム自体の進化によるカテゴリ消滅**。

### 2026年時点の現実

1. **ChatGPT Custom GPTs** — URL入力→分析のGPTを誰でも作れる。すでにLP分析系GPTが数十個存在
2. **Claude Projects** — 固定プロンプト + URLで同等のことが可能
3. **Claude Code / Cursor** — 開発者は自分でスクリプトを書いて回す
4. **Perplexity等のAI検索** — URL分析機能の拡充が進んでいる

### カテゴリ消滅のタイムライン予測

| 時期 | イベント | Publish Gateへの影響 |
|------|---------|-------------------|
| 現在 | Custom GPTs/Claude Projectsで70%再現可能 | プロンプトを書ける人は来ない |
| 6ヶ月以内 | GPT/Claude がMCPでブラウザ操作標準化 | DOM取得+Vision が汎用化、技術差ゼロに |
| 12ヶ月以内 | AIネイティブのマーケSaaS（Jasper, Copy.ai等）がLP分析機能追加 | 既存顧客基盤を持つ競合が同機能を内包 |
| 18ヶ月以内 | Google自体がSearch Console内でAI分析提供 | 権威あるデータ+無料。勝ち目なし |

## 4. では何が「防御可能」か？

### 防御不可能なもの（諦めるべき）

- **技術的優位性** — LLMラッパーに技術モートはない
- **プロンプト品質** — リバースエンジニアリング可能。出力を見れば推測できる
- **単発分析の価値** — 1回の分析は ChatGPT で代替される

### 防御可能な可能性があるもの

| 防御線 | 現状の実装 | 必要なアクション |
|--------|-----------|----------------|
| **データの蓄積** — 分析履歴×改善結果のペアデータ | ❌ 未実装（in-memory store） | GA4連携で「施策→結果」のフィードバックループを作る |
| **ワークフロー統合** — 分析→依頼→実行→計測の一気通貫 | △ 依頼パックまで | Asana/Notion/Slack連携で「離脱コスト」を作る |
| **チーム標準化** — 組織内の共通言語・テンプレート化 | ❌ 未実装 | 七條型の「チーム全員の足並みを揃えたい」ニーズ |
| **バイラル設計** — 共有URLの再帰的拡散 | △ 実装あり | 実際に回るかはβテスト次第 |
| **規制対応の深度** — 薬機法DBなど独自データ | △ プロンプト依存 | 実際の行政指導事例DBを構築すれば差別化 |
| **業界特化** — LP業界の暗黙知のプロダクト化 | △ プロンプトに内包 | ヒューリスティクスのルールエンジン化 |

## 5. 率直な評価

### Publish Gateの現在地

```
技術的モート:        ★☆☆☆☆  (ほぼゼロ)
プロンプト品質モート: ★★☆☆☆  (一時的優位)
UX/ワークフロー:     ★★★☆☆  (URL入力→結果の体験は良い)
データモート:        ★☆☆☆☆  (蓄積なし)
ネットワーク効果:    ★☆☆☆☆  (共有URLの設計はあるが未検証)
スイッチングコスト:  ★☆☆☆☆  (ゼロ。データロックインなし)
```

### ChatGPT/Claude Codeに対する唯一の勝ち筋

**「プロンプトを書けない人」×「繰り返し使う人」×「チームで共有する人」の交差点**

つまり：
1. **認知コストゼロ** — URL入れるだけ（プロンプト設計不要）
2. **一貫した品質** — 毎回同じフォーマット（チーム内で共通言語化）
3. **累積価値** — 使うほど改善履歴が溜まり、比較できる（← 現状未実装が致命的）
4. **共有可能** — 結果URLをSlackに貼るだけ（← ここは強い）

### 最も重要な問い

> **「URL入力→分析結果」の単発体験に月¥4,980払うか？**

ChatGPTのPlusプラン（月$20）で同等のことが月に何度でもできる中で、この問いにYesと言わせるのは極めて難しい。

**勝負は「単発分析」ではなく「継続的な改善サイクルのプラットフォーム」に移行できるかどうか。** 現在のMVPは単発分析で止まっているため、このままではスイッチリスクは非常に高い。

## 6. 推奨アクション（優先順）

1. **β検証の焦点を変える** — 「分析品質」ではなく「共有URL経由で誰かに渡したか」「2回目の分析をしたか」を見る
2. **履歴・比較機能を最優先で実装** — 「前回と何が変わったか」が見えればChatGPTでは代替不能
3. **依頼パック→タスク管理連携** — 分析結果がそのままAsana/Notionタスクになれば離脱コスト発生
4. **GA4/GSCデータとの統合を前倒し** — 「実データに基づく分析」はChatGPTブラウジングでは不可能
5. **Custom GPTsを自ら出す** — 競合ではなくファネルとして使う。Custom GPTで無料体験→本体に誘導
